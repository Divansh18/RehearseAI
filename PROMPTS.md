# Interview prompts

The active assigned-interview decision prompt is [assigned_decision.txt](src/rehearse_ai/prompts/assigned_decision.txt); the active terminal prompt is [assigned_closing.txt](src/rehearse_ai/prompts/assigned_closing.txt). These files are loaded at runtime and remain authoritative. `tts_style.txt` is the existing voice-shaping instruction.

The assigned decision input includes the immutable plan, exact current question, topic and follow-up guidance, candidate-specific focus areas, answers by question, last delivered/interrupted prompt, and corrected session memory. Candidate speech and memory are untrusted content. The model proposes a validated action; Python enforces order, required coverage, probe counts and permitted text. A proposed covered future question requires an exact quote from a collected answer; Python validates it and records the source turn. Explicit stop, repeat, skip and correction handling precede inference. Feedback requests receive a refusal without consuming a probe. Closing is a short professional sign-off without assessment, scores, suggestions or outcome promises.

Older practice-coach prompts (`opening_ack.txt`, `decision.txt`, `feedback.txt`, `early_feedback.txt`) remain only for historical controller/regression compatibility. They cannot be selected through the invitation WebRTC entry, which requires an assigned plan. They must be retired with tests in a separate runtime refactor. The earlier [recorded take-home session](https://www.loom.com/share/928bba7d68ec4174856488a0ed2e1bb7) used fixed project questions and coaching feedback; it is historical evidence, not a current prompt evaluation. No real-model evaluation of assigned-interview relevance or microphone session has been completed. Mocked routing tests establish limits, not naturalness.
