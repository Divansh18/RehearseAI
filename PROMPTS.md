# Interview prompts

## Live interview

The active assigned-interview decision prompt is [assigned_decision.txt](src/rehearse_ai/prompts/assigned_decision.txt); the active terminal prompt is [assigned_closing.txt](src/rehearse_ai/prompts/assigned_closing.txt). These files are loaded at runtime and remain authoritative. `tts_style.txt` is the existing voice-shaping instruction.

Each decision receives a **bounded context**, not the plan: `interview_context` (title, purpose, style), `current_question` (the exact question, topic and its own follow-up guidance), `remaining_topics` (short topic labels of later unasked questions, used only to recognise earlier coverage), clipped `prior_answers`, the answer so far, `latest_candidate_turn`, corrected `session_memory` and overlays, `last_delivered_prompt`, `interrupted_prompt`, `candidate_focus_areas`, `remaining_follow_ups` and `time_pressure` (`normal`, `tight`, `exhausted`). Future question text and guidance, the grounding evidence and notes, and the administrator's private instructions are not sent. The closing prompt additionally receives `closing_instructions` and `ended_for_time`. Candidate speech and memory are untrusted content. The model proposes a validated action; Python enforces order, required coverage, probe counts, the time budget and permitted text. A proposed covered future question requires an exact quote from the latest turn, which Python validates. Explicit stop, repeat, skip and correction handling precede inference. Feedback requests receive a refusal without consuming a probe. The closing is a short professional sign-off without assessment, scores, suggestions or outcome promises.

This reduction limits what the model is *given*. It is not a guarantee about what it *says*: spoken text is checked only for length, question count and (for the closing) feedback vocabulary. Follow-up guidance for the current question can still influence a spoken follow-up.

## Plan preparation

[plan_prepare.txt](src/rehearse_ai/prompts/plan_prepare.txt) turns the résumé, job description, private instructions and duration into a structured plan (structured-output schema in `preparation.py`). [plan_revise.txt](src/rehearse_ai/prompts/plan_revise.txt) applies one natural-language change and returns the complete plan. Documents, instructions and requests are untrusted data. Rules include: no invented experience, résumé-based questions must carry a verbatim résumé span, no protected-characteristic questions, no scoring or hiring guidance, closing as a tone note without outcome promises. The output is validated in Python and is never trusted because the prompt says so. The prompts are versioned with the application; the digest stored on each record covers every file in `src/rehearse_ai/prompts/`.

## Historical practice prompts

`opening_ack.txt` is now used live: after the candidate's reply to the greeting, one short, neutral acknowledgement (its only input is the candidate's reply; the confirmed name appears only in a Python greeting template, never in a prompt). The output is validated and falls back to a fixed neutral line. Older practice-coach prompts (`decision.txt`, `feedback.txt`, `early_feedback.txt`) remain only for historical controller/regression compatibility. They cannot be selected through the invitation WebRTC entry, which requires an assigned plan. They must be retired with tests in a separate runtime refactor. The earlier [recorded take-home session](https://www.loom.com/share/928bba7d68ec4174856488a0ed2e1bb7) used fixed project questions and coaching feedback; it is historical evidence, not a current prompt evaluation. No real-model evaluation of assigned-interview *conversation* quality or microphone session has been completed; mocked routing tests establish limits, not naturalness. Plan-preparation checks with a real model are recorded in [PLAN_PREPARATION_CHECKS.md](PLAN_PREPARATION_CHECKS.md).
